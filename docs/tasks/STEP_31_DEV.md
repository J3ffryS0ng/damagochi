## 목표·선행

현재 게임 화면에서 랜덤 주기로 내부 응가 생성 요청을 발생시키는 Timer를 추가한다. STEP30 필수AC 통과·PASS WITH ISSUE 완료 및 현재 두 제품 검증해시 일치 확인. BUG005 종료 관찰은 비차단 후속이며 BUG003/004도 유지한다.

## M-016 제안 — 확정 전 구현 금지

- **A 권장:** 유효 대기시간60~120초 사이에서 매회 균등 무작위 간격을 뽑는다. 평균90초로 게임 화면에서 비교적 자주 요청된다.
- **B:**120~180초, 평균150초. 후속 응가 표시 연결 시 돌봄 빈도가 더 낮다.
- 공통: 현재 활성 대상이baby이고 부화빛이 완전히 끝난 시점에 첫 간격을 뽑아 시작한다. 알/빈데이터/미지원stage/부화 중에는 요청하지 않는다.
- 먹기/놀이 중에는 남은 시간을 보존하며 타이머를 일시정지한다. 완료 또는 취소 후 같은 대상이 유효하면 남은 시간부터 재개한다. 행동을 방해하거나 완료 직후 누적 요청을 몰아서 보내지 않는다. 따라서 실제 벽시계 간격은 행동시간만큼 늘어날 수 있다.
- 만료당 내부 poop_requested 신호1회 후 새 간격을 뽑는다. 장시간 프레임 지연에도 누락 시간분을 여러 번 보충하지 않는다. 신호 시점의 대상 자격을 다시 확인한다.
- 동일 대상 반복갱신은 타이머·신호연결·남은 시간을 유지한다. 대상교체(같은내용 다른Dictionary 포함)/자격상실/장면이탈은 정리·초기화한다. 다시 유효해지거나 Game재진입 시 전체 새 간격에서 시작한다.
- 게임화면을 벗어난 시간/앱이 실행되지 않은 시간의 누적·오프라인 발생·남은시간 저장은 이번에 없다(STEP90후속). Tree의 실제 pause 시에도 진행하지 않는다. 단순 창 비활성은 기존 게임 실행정책을 따른다.
- 응가 개수상한/배치/생성거부·청소 후 주기는 이번 소비자 없는 신호로 확정하지 않는다. STEP32/33 작업카드에서 생성물 수명과 함께 결정한다. 새 결정이 필요하면 기존신호 계약과 조정한다.

허용: game.gd, 필요시 Game.tscn, 신규 tests/step_31 및 카드/보고/상태문서. 자산·managers·저장규격·기존카드/보고/검사·COMMON 템플릿 유지. Timer 전용 난수원을 사용해 평소 이동난수와 결합하지 않는다.
