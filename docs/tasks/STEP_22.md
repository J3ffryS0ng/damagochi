# STEP 22 작업 카드 — 캐릭터 Idle 이미지 및 애니메이션

작성일: 2026-09-13 / 상태: 선행 검증 대기 / 담당: 개발 관리자 → 구현 → 검증 순차 수행.

2026-09-13 구현 준비 갱신: 이 파일은 개요 카드다. DEV는 `docs/tasks/STEP_22_DEV.md`의 S22-DEV-001을 사용한다. 세부 수정 범위·구현 지침·테스트·BLOCKER를 그 카드에 정의했다. 22-P1은 준비 완료이며 STEP 전체는 선행 검증 대기를 유지한다. Idle 연출 선택은 DECISION_LOG.md M-004를 따른다.

## 목표와 입력

부화 직후와 저장 복원 후 캐릭터가 표시되고 대기 애니메이션이 반복된다.

먼저 PROJECT_STATE.md, BUG_LOG.md, DECISION_LOG.md와 기존 진행표를 읽는다. PROJECT_SPEC.md·STEP_PLAN.md가 제공되면 그 요구와 이 카드를 대조한다.

22-P에서 시작 흐름 수정이 필요하면 별도 선행 복구 단위로 기록한다. name_entry.gd 수정은 Idle 연출 변경과 구분한다. 선행 문제가 남으면 STEP 22 완료 판정을 보류한다.

## 검증 시나리오

1. 원본 저장을 덮어쓰지 않는 별도 테스트 환경을 준비하고 적용 여부를 확인한다.
2. 메인 메뉴 → 새 이름 → 게임 진입. 알 표시, 기존 흔들림, 입력당 친밀도 증가를 확인한다.
3. 레벨/시간 조건 미충족 시 부화하지 않고, 두 조건 충족 후 기존 판정 호출에서 한 번만 부화한다.
4. 부화 빛 효과 후 캐릭터가 표시되고 Idle이 반복된다. 알·터치 영역 상태가 기존 의도대로 전환된다.
5. 종료 후 baby 상태를 복원하면 이미지와 Idle이 바로 표시된다.
6. 화면/데이터 갱신을 반복해도 애니메이션이 중복 생성되거나 위치·크기가 누적되지 않는다.
7. 마우스 및 가능한 터치 검증, 장면 재진입, 오류 로그를 확인한다. 수행 불가 항목은 미검증으로 남긴다.

## 제외 및 완료 판정

랜덤 좌우 이동, 밥주기, 데이터 기반 캐릭터 확장, 새 저장 규격은 후속 STEP이다. 모든 관련 완료 조건을 만족한 뒤 STEP 23으로 이동한다. 이번 조사에서는 구현·회귀 테스트·완료 체크·커밋을 하지 않았다.
