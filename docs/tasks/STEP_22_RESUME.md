## 목표 / 확정 정책

MainMenu에서 이어하기와 새 게임을 구분한다. 이어하기는 파일에서 읽은 기존 egg/baby를 Game으로 전달하고 초기화·불필요한 저장을 하지 않는다. 기존 파일이 있으면 새 게임을 누른 즉시 대체 가능성을 확인하고, 확인 후에만 NameEntry로 이동한다. 취소는 현재 메뉴와 메모리·저장 파일을 보존한다. 이름 입력·검증·새 게임 저장·Game 이동 흐름은 유지한다.

읽기 실패는 삭제·자동 덮어쓰기·자동 새 게임을 유발하지 않는다. 오류를 표시하고 메뉴에 머무른다. 읽을 수 없는 파일에서도 사용자가 별도로 새 게임을 누르고 대체를 확인한 경우에만 기존 이름 입력 흐름으로 갈 수 있다. 이는 읽기 실패에 따른 자동 초기화가 아니라 사용자가 선택한 새 게임이다.

M-005 과거 제안은 이름 입력 후 최종 저장 직전 확인이었지만, **사용자 확정은 NameEntry 진입 전 확인**이다. DEV는 과거 제안의 순서를 적용하지 않는다. 확인 버튼을 눌러도 그 자리에서 파일 삭제·새 데이터 생성·저장을 하지 않는다. 실제 대체 시점은 기존처럼 유효 이름을 제출해 새 게임 저장이 성공할 때다.

## 구체적인 구현 요구사항

### R1 메뉴 UI

기존 VBoxContainer 안에 ContinueButton을 StartButton 앞에 추가한다. 텍스트는 각각 ‘이어하기’, ‘새 게임’이며 기존 버튼 크기 280×70과 글꼴 24, 간격 20을 기준으로 맞춘다. StartButton 노드 이름은 유지해 기존 참조를 보존한다. EncyclopediaButton과 동작은 유지한다.

VBoxContainer에 MessageLabel을 추가해 오류를 줄바꿈 표시한다. MainMenu 직속 ReplaceSaveDialog(ConfirmationDialog)를 추가한다. 문구는 ‘새 게임을 시작하면 기존 진행 데이터가 대체될 수 있습니다. 계속하시겠습니까?’, 확인 ‘새 게임 진행’, 취소 ‘취소’로 한다. 읽기 실패 상태에서는 ‘기존 저장을 읽을 수 없습니다. 새 게임 저장 시 해당 파일이 대체될 수 있습니다.’를 추가한다.

Dialog 취소·Esc·닫기는 모두 같은 취소 동작이다. 확인/취소 신호는 한 번만 연결하고 열린 동안 중복 입력으로 여러 전환을 만들지 않는다. 취소 후 직전 메뉴 문구·버튼 상태·새 게임 버튼 포커스를 유지한다.

메뉴 _ready에서는 임시 Dictionary로 파일 상태를 검사한다. 검사 실패 결과를 GameManager.load_game_data에 넘기지 않는다. 기존 메모리가 있어도 그것을 디스크 로드 성공으로 대신하지 않는다. 새 게임 버튼 클릭 시에는 파일 존재를 다시 확인한다. 이어하기 클릭 시에도 로드·검사를 다시 수행해 클릭 사이 읽기 실패에 대응한다.

### R3 최소 로드 검사와 이어하기

검사는 main_menu.gd의 순수 helper로 구현한다. SaveManager.load_game()의 빈 결과·잘못된 JSON·읽기 실패는 오류로 처리한다. 추가로 GameManager 호출 전에 다음 조건을 확인한다.

- player_name은 비어 있지 않은 String, save_version은 숫자 1, active_creatures는 비어 있지 않은 Array이며 각 요소는 Dictionary여야 한다.
- 각 creature_id는 비어 있지 않은 String이어야 한다. 존재하는 stage는 비어 있지 않은 String이어야 하며 egg/baby를 지원한다. 다른 문자열 stage를 임의 egg로 초기화하지 않는다. 이번 AC5 시험 대상은 egg/baby이며 다른 단계의 동작을 새로 설계하지 않는다.
- 존재하는 level은 유한한 정수값 숫자 ≥1, affection은 유한한 정수값 숫자 ≥0, affection_to_next_level은 유한한 정수값 숫자 ≥1이어야 한다. JSON 숫자는 float일 수 있으므로 TYPE_INT만 강제하지 않는다.
- 존재하는 egg_created_at/hatched_at은 유한한 숫자 ≥0이어야 한다. 필드가 없을 때 GameManager가 이미 제공하는 stage/level/affection/목표/시간 기본값 보완은 유지한다. 모든 필드가 있는 정상 저장의 값은 보존한다.
- 예상 외 선택 필드와 미지 키는 제거하지 않는다. 이 검사는 현재 GameManager의 타입 변환과 친밀도 무한 반복 위험을 피하는 진입 방어이며 저장 마이그레이션·전체 BUG-004 해결 선언이 아니다.

검사 통과 후 기존 GameManager.load_game_data 결과를 확인하고 res://scenes/game/Game.tscn으로 전환한다. 실패 시 메뉴의 MessageLabel에 ‘저장 데이터를 읽을 수 없습니다. 기존 저장은 변경하지 않았습니다.’ 또는 장면 전환 실패를 표시하고 머문다. 성공 전환 중에는 재입력을 막고 실패 시 버튼 상태를 복구한다.

이어하기 경로에서 create_new_game, clear_game_data, save_game, delete_save를 호출하지 않는다. 기존 데이터는 깊은 복제로 보관해 load/전환 실패 시 이전 메모리로 복구할 수 있게 한다. 메뉴의 읽기·전환만으로 파일 바이트가 바뀌어서는 안 된다.

단, Game 진입 후 **기존 알 부화 조건을 만족해 원래 게임 로직이 부화·저장하는 것**은 정상 진행이다. 이를 ‘이어하기 중 덮어쓰기 금지’로 해석해 기존 부화를 막지 않는다. 단순 보존 테스트는 부화 조건 미충족 egg와 baby로 수행하고, 조건 충족 egg의 자연 부화는 별도 회귀 항목으로 확인한다.

### R4 새 게임 확인 및 NameEntry 전달

기존 파일 없음 → 새 게임 승인 정보 생성 → NameEntry. 파일 있음 → Dialog → 확인 시에만 승인 정보 생성 → NameEntry. 취소는 Dialog만 닫고 GameManager·저장·메뉴 상태를 유지한다. 읽기 실패 파일도 이 명시적 절차를 거치며 자동 진행하지 않는다.

승인 전달은 SceneTree의 런타임 메타데이터(키 예: step22_new_game_authorization)를 사용해 저장 스키마나 GameManager를 바꾸지 않는다. 승인에는 확인 당시 파일 존재 여부와 기존 파일의 SHA256을 포함한다. 파일이 없으면 ‘없음’ 상태를 보관한다. 파일은 존재하나 바이트 읽기도 실패해 해시를 얻을 수 없으면 ‘기존 저장을 확인할 수 없어 새 게임을 진행할 수 없습니다.’ 안내 후 안전하게 메뉴에 남는다. 잘못된 JSON이지만 바이트를 읽을 수 있으면 해시를 얻어 명시적 대체 확인을 진행할 수 있다.

NameEntry는 _ready에서 승인 정보를 가져와 로컬 변수로 보관하고 전역 메타데이터를 제거한다. 승인 없이 직접 진입한 경우에는 저장하지 말고 MainMenu로 돌려보낸다. 뒤로 가기는 로컬 승인을 버리고 기존 메모리·파일을 유지한다. 이름이 비어 있으면 기존 오류 안내를 유지하며 저장하지 않는다.

유효 이름 제출 시 승인 당시와 현재 파일 존재/해시가 같은지 확인한다. 파일이 생기거나 바뀌었거나 읽을 수 없으면 새 데이터를 생성하지 않고 ‘저장 상태가 변경되었습니다. 뒤로 돌아가 다시 새 게임을 선택해 주세요.’를 표시한다. 이는 메뉴에서 받은 확인이 다른 저장까지 덮어쓸 권한으로 재사용되는 것을 막는 처리다. 확인 Dialog를 이름 제출 시 다시 추가하지 않는다.

기존 메모리를 깊게 보관한 뒤 기존 create_new_game/save_game 흐름으로 진행한다. 저장 실패는 기존 안내·return과 함께 이전 메모리를 복원한다. 성공 후 승인 정보를 무효화하고 기존 Game 전환을 유지한다. 새 게임 확인 자체에는 파일을 삭제하지 않는다. 이 작업은 SaveManager의 원자적 쓰기까지 바꾸지 않으므로 디스크 장애 중 부분 쓰기 보장 문제는 기존 한계로 보고하고 범위를 확대하지 않는다.

### R5 오류와 반복 입력

Dialog 확인 연타·이름 확인/Enter 연속 입력에서 새 게임 생성·저장·전환이 중복되지 않게 전환 중 가드를 둔다. 실패 시 재시도 가능한 상태를 복원하되 파일 상태 확인을 생략하지 않는다. 정상 복원 실패를 ‘저장 없음’으로 바꿔 자동 새 게임으로 보내지 않는다. 메시지는 콘솔 로그만이 아니라 화면에서 볼 수 있어야 한다.

정상 fixture는 GameDataFactory로 생성해 별도 테스트 저장에만 기록한다. 잘못된 구조 fixture는 빈 배열·배열 아닌 값·요소 타입 오류·0 임계값·비숫자 값을 포함하며 Game으로 보내기 전에 차단되는지 확인한다. BUG-004를 재현하려고 무한 반복 가능한 값을 GameManager에 직접 전달하지 않는다.

테스트는 기존 run.ps1의 고유 사본/격리 user:// 패턴을 재사용한다. 실제 엔진 해석 저장 경로와 원본 저장 해시 전후를 기록한다. 원본 사용자 저장을 삭제하거나 잘못된 fixture로 덮어쓰지 않는다. 신규 UI 노드의 신호·버튼 표시·Dialog 확인/취소 및 실제 마우스 클릭 영역을 QA가 확인한다. 실기기 터치와 Idle 체감 품질은 사용자 환경 미검증 목록으로 유지하고 수행한 경우만 결과를 바꾼다.

## 예상 영향 / 알려진 한계

MainMenu의 저장 상태별 표시와 NameEntry의 승인 진입 계약이 바뀐다. 기존 이름 입력 흐름과 도감 버튼은 유지한다. 직접 NameEntry를 실행하는 테스트는 승인 없는 진입 거부를 기대해야 한다. 기존 QA의 ‘NameEntry로 잘못 이동함’ assertion을 성공 회귀 기준으로 남기지 않는다.

BUG-002는 정책 결정만으로 해결되지 않는다. S22-DEV-002 구현·RC01~14/AC5 QA 후 잔여 해결을 판정한다. BUG-003 자동 부화 요구, BUG-004 전체 저장 검증, Game 메뉴 버튼, 원본 이미지 배경 등은 별도 범위다. STEP 23 착수 및 STEP 22 전체 완료는 관리자 판정 전 보류한다.
