## 구현 범위와 중단 지점

목표는 baby 캐릭터가 지정 영역 안에서 랜덤 좌우 이동하고 기존 Idle이 함께 유지되는 것이다. 수정 대상은 scripts/game/game.gd, 필요 시 scenes/game/Game.tscn과 tests/step_23 신규 검사다. 별도 이동 노드 또는 x/y 속성 분리 중 코드 구조에 맞는 방법을 DEV가 선택하되, 기존 알·클릭 영역·UI는 이동시키지 않는다. 현재 Idle이 CreatureSprite.position 전체를 Tween하므로 독립 이동 코드가 같은 속성을 덮어쓰는 방식은 금지한다.

M-008에 따라 이동 범위 ±120px와 원본 외형 방향 유지는 확정했다. A/B 속도·대기 수치는 사용자 결정 후 확정하며 그 전에는 DEV 구현에 착수하지 않는다. 재진입 위치를 저장하려면 공용 저장 규격 변경이므로 별도 결정이 필요하다. 이번 제안은 런타임 이동만 사용한다.

제외: STEP 24 밥주기, 이동 중 조우, 다중 캐릭터, 걷기 프레임 제작, 부화 규칙·친밀도·메뉴 정책·저장 규격 변경, 기존 BUG-003/004 전체 해결.

## 검증 운영

실제 사용자 저장을 건드리지 않는 격리 실행환경을 먼저 확보한다. Godot 4.7.2에서 파싱·장면 로드, 자동화 시나리오, 가능한 실제 렌더를 검증한다. 기존 tests/step_22의 verify, qa_verify, resume_verify, resume_qa_verify 중 관련 회귀를 실행한다. 기존 정지 x 가정은 승인된 이동 명세에 맞게 STEP 23 검사에서 분리하되 기존 테스트 파일과 이력은 덮어쓰지 않는다.

QA는 카드·실제 코드를 다시 읽고 DEV PASS와 별개로 실행한다. 정상 메뉴를 건너뛰는 직접 Game 테스트만으로 AC4를 PASS 처리하지 않는다. 로그에 기대 결과·관측·환경·조건별 PASS/FAIL/미검증/사용자 확인 필요를 구분한다. 실제 물리 입력·기기 터치·연출 체감의 미검증을 자동화 통과로 대체하지 않는다.

일반 구현 FAIL은 최대 3회 DEV 수정 → 자체검증 → QA 재검증한다. 제품/정책 결정은 즉시 MANAGER에게 반환하고 사용자 결정 전 멈춘다. 사용자 환경의 비차단 품질 확인과 필수 기능 미검증을 구분한다.
