## M-012 제안 — 확정 전 구현 금지

- A 권장: 정상 완료마다 친밀도 +1. 기존 알 터치와 같은 증가 단위로 성장 속도를 보수적으로 유지한다.
- B: 정상 완료마다 +3. 같은 급식 횟수에서 더 빨리 레벨업한다.
- 공통: 음식 페이드아웃까지 끝난 시점에 시작 당시 대상에게 1회만 반영. 접근/몸짓/페이드 중 취소·장면 이탈·자격 상실 또는 대상 교체는 0회. 연출 중 추가 입력은 기존처럼 무시, 새 쿨다운 없음. 완료 함수 중복 호출이나 오래된 콜백도 중복 지급하지 않는다.
- 기존 GameManager.add_affection의 레벨업 규칙을 재사용하고 이름/LV/친밀도/게이지를 갱신한다. 기존 SaveManager로 즉시 저장. 저장 버전·필드·경로는 유지한다.
- 친밀도 처리 거부 또는 SaveManager의 명시적 실패 반환 시 이번 증가 및 그로 인한 레벨/임계값 변화를 메모리에서 되돌리고 화면에 실패 안내. 정상 이동/Idle·버튼으로 복귀, 자동 재지급·재시도·보상 큐 없음. 다음 사용자 급식은 새 사이클이다. 저장 쓰기 시작 거부에서는 기존 파일 바이트 보존 확인.
- 기존 저장기는 쓰기 도중 오류 검출·원자적 교체를 보장하지 않는다. 물리 디스크 장애·부분 기록 복구는 BUG-004 안정화 후속이며, 위 메모리 복구를 디스크 트랜잭션 보장으로 표현하지 않는다.

범위: game.gd, 필요 시 Game.tscn(실패 안내), tests/step_27 및 보고/상태 문서. 기존 managers의 공개 계약·전역 저장 규격·알 터치 정책은 유지. 먹기 보상 진입부는 유한 수치·양수 임계값 등 필요한 최소 검사를 두어 BUG-004의 무한 반복 경로를 호출하지 않도록 한다. 전체 저장 로더 개편은 범위 밖이다. 그 범위가 필요하면 결정/BLOCKER로 보고한다.
